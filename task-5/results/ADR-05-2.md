### <a name="_qmphm5d6rvi3"></a>**Решение**

Для простоты начальной версии предлагается реализовать отправку оповещений по электронной почте через внутренний сервер.

Общая схема работы системы оповещений будет такая:

```
App (Spring Batch)
        │  metrics
        ▼
Prometheus (rule evaluation)
        │  alerts (HTTP POST)
        ▼
Alertmanager ─── SMTP ───► Mailhog (catches email, web UI at :8025)
```

Для отправки оповещений выбран **Prometheus alertmanager**.

Prometheus уже собирает метрики из приложения, поэтому не нужно поднимать дополнительные компоненты. Alertmanager идёт в комплекте с Prometheus и настраивается простыми YAML-файлами, которые можно хранить в репозитории вместе с кодом. Правила оповещения гибко настраиваются: можно задать порог срабатывания и задержку перед отправкой уведомления, чтобы избежать ложных срабатываний из-за кратковременных скачков.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

**Grafana alerting**

Grafana alerting — встроенная в Grafana система оповещений, которая позволяет создавать правила прямо в интерфейсе и настраивать каналы уведомлений без работы с конфигурационными файлами Prometheus.

**Недостатки, ограничения, риски**

1. Нет встроенного веб-интерфейса для управления правилами — все настройки через YAML-файлы.  
*Меры: хранить конфигурацию в репозитории и управлять правилами через pull-запросы, а для просмотра использовать Grafana.*

2. Alertmanager требует отдельного контейнера и настройки SMTP, что усложняет начальное развёртывание.  
*Меры:  автоматизировать развёртывание через docker-compose и вынести конфигурацию в отдельный файл.*

3. Сложно быстро отключить или изменить алерт без перезапуска Prometheus.  
*Меры: использовать метки и аннотации в правилах, а также управлять включением алертов через Git-ветки или переменные окружения.*
