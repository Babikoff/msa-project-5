### <a name="_qmphm5d6rvi3"></a>**Решение**

Для мониторинга выбраны системные метрики JVM и приложения: **process_cpu_usage** для оценки загрузки процессора пакетным заданием, **jvm_memory_used_bytes** для контроля использования памяти и обнаружения утечек, **jvm_gc_pause_seconds** для анализа пауз сборки мусора, **hikaricp_connections_active** для мониторинга пула соединений к базе данных PostgreSQL. Также собираются метрики времени запуска приложения **application_started_time_seconds** и **application_ready_time_seconds**, а также метрики выполнения Spring Batch job и шагов. Эти метрики важны, потому что batch-обработка интенсивно использует процессор и память, а нагрузка на базу данных определяет общую производительность импорта данных.

В качестве библиотек выбраны **spring-boot-starter-actuator, micrometer-registry-prometheus и spring-boot-starter-web**. Actuator предоставляет готовый endpoint /actuator/prometheus и интеграцию с Micrometer без написания кода. Micrometer Prometheus registry выставляет метрики в формате, понятном Prometheus, и не требует установки отдельного агента или запуска дополнительного контейнера. Библиотека spring-boot-starter-web добавляет встроенный веб-сервер, через который endpoint становится доступен на порту 8080. Это решение подходит лучше всего, так как требует минимальных изменений в коде, не увеличивает инфраструктуру и использует уже настроенные в docker-compose.yml цели скрапинга и дашборд Grafana.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

**Prometheus Agent** - это отдельный компонент, который собирает метрики с приложений и пересылает их на сервер Prometheus через remote write. Он подходит для случаев, когда цели недоступны для прямого скрапинга, но в данной задаче приложение и Prometheus работают в одной сети Docker, поэтому агент был бы избыточным компонентом.

**JMX Exporter** - это Java агент, который выставляет JMX метрики в формате Prometheus. Для его использования нужно добавить аргумент запуска JVM и открыть отдельный порт, кроме того имена метрик отличаются от тех, которые использует Micrometer, что потребовало бы изменения конфигурации Prometheus и дашборда Grafana.

**Недостатки, ограничения, риски**

Счетчики метрик хранятся в памяти приложения и сбрасываются при перезапуске контейнера, что может создать провалы на дашбордах. Приложение зависит от доступности базы данных PostgreSQL, и при её недоступности метрики приложения могут быть недоступны.
