### <a name="_qmphm5d6rvi3"></a>**Решение**

Для решения данной задачи предлагается использовать **Apache Airflow**. В таблице ниже обосоновывается соответствие данного решения функциональным требованиям.

|**№**|**Требование**|
| :-: | :- |
| F1 | Возможность ветвления процессов - есть: через BranchPythonOperator, добавления условных операторов через BranchPythonOperator и Sensor-ы, event-triggers через Trigger Rules |
| F2 | BigQuery - есть: BigQueryInsertJobOperator, GCSToBigQueryOperator, BigQueryToGCSOperator |
| F3 | Redshift - есть: через RedshiftSQLOperator, RedshiftDataOperator, S3ToRedshiftOperator |
| F4 | Kafka - есть: через ProduceToTopicOperator, ConsumeFromTopicOperator |
| F5 |Spark - есть: через SparkSubmitOperator, SparkJDBCOperator, SparkSqlOperator |
| F6 | Есть: fallback- через trigger_rule="all_failed" или "one_failed", retry - через параметр retries PythonOperator |
| F7 | Email - есть |
| F8 | Стандртная установка как приложения есть везде, в Google Cloud, Microsoft Azure, AWS есть дополнительные возможности |

Таким образом видно, что предлагаемое решение покрывает все требования. Также Airflow рассчитан на высокие нагрузки, что и требуется в данном проекте.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

**Spring Batch**

**Недостатки:** 
выполняется только на одной ноде - нет возможности масштабирования. В приниципе не может решить задачу справиться с повышением нагрузки.

*Отклонено.*

**Spring Cloud Data Flow (SCDF)**

**Недостатки**:
- Сложность развёртывания и эксплуатации: требует установки и поддержки нескольких компонентов (SCDF Server, Skipper, task runners), что увеличивает операционные издержки по сравнению с монолитной установкой Airflow.
- Ограниченная гибкость в описании сложных пайплайнов: SCDF ориентирован на линейные задачи и потоки; реализация условного ветвления, динамической маршрутизации и сложных DAG существенно сложнее, чем через BranchPythonOperator и Trigger Rules в Airflow.
- Отсутствие нативных интеграций с аналитическими хранилищами: для BigQuery и Redshift нет готовых компонентов, интеграция требует кастомной разработки, в то время как Airflow предоставляет готовые операторы (BigQueryInsertJobOperator, RedshiftSQLOperator и т.д.).
- Слабая поддержка уведомлений из коробки: встроенных механизмов отправки email-уведомлений нет, требуется настройка внешних систем мониторинга или кастомная разработка.
- Более высокий порог входа: требует знаний экосистемы Spring (Spring Boot, Spring Cloud Stream, Spring Cloud Task), что сложнее для команды, чем Python-базисный Airflow.
- Менее зрелый интерфейс мониторинга и управления задачами по сравнению с Airflow UI.

Соответствие функциональным требованиям (почему SCDF хуже, чем Apache Airflow):

|**№**|**Требование**|**Почему Spring Cloud Data Flow (SCDF) хуже, чем Apache Airflow**|
| :-: | :- | :- |
| F1 | Возможность гибко формировать пайплайн работы с данными: ветвление, условные операторы, event-triggers | SCDF заточен на линейные задачи и потоки; сложное ветвление, условия и триггеры реализуются сложнее, нет эквивалента BranchPythonOperator и Trigger Rules из коробки. |
| F2 | Возможность взаимодействия с BigQuery | Нет нативных операторов для BigQuery, интеграция требует кастомной разработки; в Airflow уже есть BigQueryInsertJobOperator, GCSToBigQueryOperator, BigQueryToGCSOperator. |
| F3 | Возможность взаимодействия с Redshift | Нет нативных операторов для Redshift, интеграция требует кастомной разработки; в Airflow уже есть RedshiftSQLOperator, RedshiftDataOperator, S3ToRedshiftOperator. |
| F5 | Возможность взаимодействия с Spark | Поддержка Spark ограничена задачами Spring Cloud Task, нет гибких операторов вроде SparkSubmitOperator, SparkJDBCOperator, SparkSqlOperator. |
| F6 | Наличие настроек для применения fallback-logic и retry паттерна | Ограниченные встроенные механизмы повторов и обработки ошибок по сравнению с trigger_rule и параметром retries в Airflow. |
| F7 | Возможность отправки email-уведомлений | Нет встроенных механизмов отправки email, требуется дополнительная настройка или интеграция с внешними системами мониторинга. |

*Отклонено.*

**Недостатки, ограничения, риски выбранного решения Airflow**

1. **Сложность настройки и администрирования** — требует ручного управления зависимостями, окружением и конфигурацией scheduler/worker; обновление версий может привести к несовместимости DAG.
   **Способ устранения:** контейнеризация через Docker/Kubernetes с описанием инфраструктуры в виде кода (Infrastructure as Code).

2. **Узкое место планировщика (scheduler) при большом количестве задач** — при росте числа DAG и задач scheduler может стать ограничением по производительности и увеличить нагрузку на метаданные БД.
   **Способ устранения:** переход с SequentialExecutor/LocalExecutor на распределённые экзекьютеры CeleryExecutor или KubernetesExecutor.
